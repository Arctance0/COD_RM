# Embedded Control System for a RoboMaster Omni-Wheeled Robot

## 项目概述

面向 RoboMaster 机器人比赛场景的嵌入式控制项目，基于大疆 RoboMaster C 型开发板 STM32F407IGHX 开发，使用 Keil、STM32 HAL、CMSIS-OS/RTOS 任务调度和 C/C++ 编译环境。项目按 Chassis 底盘工程与 Gimbal 云台工程拆分，覆盖底盘运动控制、云台姿态控制、射击机构控制、IMU 姿态解算、MiniPC 视觉通信、弹道解算、裁判系统解析、客户端 UI 绘制和超级电容/功率管理等核心比赛链路。

从工程结构上看，项目不是简单的单文件控制逻辑，而是按照 `Application/API`、`Application/Tasks`、`BSP`、`Components/Algorithm`、`Components/Controller`、`Components/Device`、`Core`、`Drivers`、`USB_DEVICE` 等层级组织代码。该结构把任务、应用接口、板级驱动、算法模块和设备组件拆开，有利于长期维护、功能复用和多人协作开发。

## 技术栈与工程环境

- 主控硬件：大疆 RoboMaster C 型开发板，STM32F407IGHX。
- 开发环境：Keil V5.38a、VS Code、Windows 11。
- 编译工具：Arm Compiler V5.06u7，C/C++ 编译。
- 底层框架：STM32 HAL、CMSIS-OS/RTOS 任务式调度、CAN、UART DMA、USB CDC。
- 控制对象：底盘电机、云台电机、摩擦轮、拨弹机构、IMU、MiniPC、裁判系统、客户端 UI。
- 关键算法：PID 双环控制、功率限制模型、RLS 参数估计框架、低通滤波、四元数姿态解算、弹道预测与补偿。

## 核心亮点

### 1. 双工程协同的机器人控制架构

项目将机器人控制拆分为 Chassis 和 Gimbal 两套工程，分别负责底盘、射击、通信、裁判系统、云台、视觉和姿态控制等功能。这样的拆分符合 RoboMaster 机器人中多控制域协同的实际需求，可以让底盘与云台分别承担高频控制任务，降低单个工程的复杂度。

在代码组织上，项目进一步按任务层、应用接口层、BSP 板级支持包、设备组件、控制器组件和算法组件分层。业务逻辑集中在 `Application/Tasks`，通用算法和设备驱动沉淀在 `Components` 与 `Application/API` 中，BSP 层承担对 STM32 HAL 的直接封装。这种层级设计让项目更接近工程化机器人系统，而不是临时拼接的比赛代码。

### 2. 毫秒级实时任务调度

项目中多个核心控制任务均以 RTOS 任务形式运行，例如底盘任务、云台任务、射击任务、通信任务和视觉任务等。底盘、云台、射击、通信等任务中普遍使用 `osDelay(1)` 或 `osDelayUntil(..., 1)` 进行周期调度，形成毫秒级循环控制链路。

这种任务式设计能够把不同实时性需求拆开处理：底盘任务负责运动解算与功率分配，云台任务负责目标角度更新与电机输出，射击任务负责摩擦轮/拨盘和热量控制，通信任务负责 CAN 数据发送、超级电容状态切换和 UI 更新，视觉任务负责与 MiniPC 进行姿态和目标数据交换。各任务职责清晰，便于定位延迟、卡顿或控制异常。

### 3. 底盘运动解算与云台跟随控制

底盘控制逻辑支持根据云台角度进行坐标变换，将遥控或键鼠输入转换到底盘坐标系下的目标速度。代码中通过 yaw 角误差计算 `COS`、`SIN`，再将输入的 `Vx`、`Vy` 转换为底盘期望速度，并根据底盘模式计算 `Vw`。

项目支持底盘跟随和小陀螺等典型 RoboMaster 模式：在跟随模式下，底盘根据云台角度误差进行 PID 计算，实现底盘朝向与云台方向的协调；在旋转模式下，底盘根据超级电容状态选择不同旋转速度。最后通过麦轮运动学关系将 `Vx`、`Vy`、`Vw` 分配到四个轮子的目标转速，完成底盘运动控制闭环。

### 4. 底盘功率限制与超级电容管理

项目实现了较完整的底盘功率控制逻辑，不只是简单限幅电机电流。功率控制模块会根据电机转速、电流、转矩估计和模型参数计算单个电机输入功率，再累加得到底盘总功率估计值。代码中还保留了 RLS 参数估计框架，用于根据实时反馈修正功率模型参数。

在功率接近上限时，系统会结合 PID 误差和各轮功率占比计算功率分配权重，将允许功率按需求分配到四个底盘电机上；如果功率未超过上限，则直接使用 PID 输出。底盘状态判断中还会根据裁判系统给出的底盘功率限制、缓冲能量和超级电容状态动态设置 `Power_Max`，使机器人在规则限制内尽可能保持运动性能。

这一部分是项目很有含金量的亮点，因为 RoboMaster 中底盘功率不是普通限流问题，而是“性能最大化”和“规则约束”之间的平衡。项目把裁判系统反馈、超级电容状态、功率模型和底盘控制闭环串起来，体现了对比赛实战约束的理解。

### 5. 云台手动/自瞄双模式控制

云台工程实现了手动控制和 AutoAim 自瞄控制两类模式。手动模式下，云台目标角度由遥控器或键鼠输入更新；自瞄模式下，如果视觉系统返回有效目标距离，则直接使用视觉解算得到的 yaw/pitch 作为云台目标，否则回退到人工输入控制。

云台控制采用角度环和速度环级联 PID：yaw 和 pitch 均有角度环与速度环，AutoAim 模式下还有独立的自瞄 PID 参数。控制逻辑中还加入了前馈项、yaw 角归一化和 pitch 机械限位，避免目标角度跳变或超过云台安全范围。最终通过 CAN 向云台电机发送控制输出，完成云台姿态闭环。

这部分可以突出项目对“人工控制”和“视觉自瞄”两种操作方式的统一管理：不是单纯接收视觉数据，而是把模式切换、目标回退、角度限制、双环 PID 和电机输出完整打通。

### 6. MiniPC 视觉通信链路

项目通过 MicroUSB/USB CDC 连接 STM32 与上位机 MiniPC，并封装了适配 `rm_serial_driver` 的数据交互函数。视觉任务会周期性向 MiniPC 发送云台姿态信息，例如 yaw、pitch、roll 等姿态数据；接收端则解析视觉系统返回的目标 pitch、yaw、distance 和是否允许开火等字段。

这一链路让嵌入式端和上位机视觉端形成闭环：下位机提供当前姿态，上位机完成目标识别与解算，下位机再根据目标角度驱动云台和射击机构。相比只做单向串口接收，这里已经具备比赛机器人常见的视觉自瞄通信框架。

### 7. 弹道预测与补偿

项目包含弹道解算模块 `api_trajectory.c`，用于把视觉识别到的目标信息转换为云台期望姿态。弹道解算会结合当前 pitch/yaw、裁判系统反馈的弹速、目标位置、目标速度、装甲板半径、yaw 角速度、系统延迟和飞行时间，预测子弹命中时刻的装甲板位置。

模块中包含目标坐标预测、装甲板选择、飞行时间估计、系统延迟补偿和 pitch 角迭代求解。对 pitch 的计算不是一次简单的 `atan2`，而是根据弹道模型反复计算高度偏差并迭代补偿，考虑了重力、弹速和弹道系数对命中点的影响。该模块把视觉识别结果进一步转化为可执行的云台控制目标，是自瞄系统从“看见目标”到“打中目标”的关键一环。

### 8. 射击热量控制与卡弹处理

射击任务不仅控制摩擦轮和拨弹电机，还根据裁判系统反馈的枪口热量上限、当前热量和冷却值动态调整发弹频率。热量充足时，系统提高拨弹速度以保证输出；热量不足时，根据剩余热量和冷却速度计算允许发射节奏，并对发弹速度进行限幅，避免因超热受到比赛惩罚。

项目还实现了拨弹机构卡弹检测和反转处理：当拨弹电机电流异常并持续一定时间后，系统进入 reload 状态，临时反转拨盘进行退弹；满足电流恢复或超时条件后再恢复正常发射。该逻辑提升了射击机构在高频连发场景下的可靠性。

### 9. 裁判系统解析与客户端 UI 绘制

项目使用 STM32 串口 DMA 与 RoboMaster 裁判系统通信：接收采用双缓存循环模式，发送采用单缓存普通模式。裁判系统数据会被解析为机器人状态、功率热量数据、RFID 状态、射速初速等信息，并进一步影响底盘功率、射击热量、UI 显示和系统状态判断。

客户端 UI 部分封装了适配裁判系统协议的数据帧编码函数，并在通信任务中周期性初始化和更新 UI。项目中包含超级电容能量条、超级电容启用状态、云台/底盘状态、视觉状态、RFID 状态和准星等 UI 元素。这样操作手可以在客户端界面中直接看到关键状态，而不是完全依赖调试串口或经验判断。

### 10. 面向比赛实战的状态保护机制

项目在多个模块中加入了状态保护和降级逻辑。例如底盘任务会根据裁判系统中的底盘/云台电源输出状态、机器人血量和超级电容状态判断是否丢失输出；云台模式切换或丢失时会重置目标 yaw/pitch，避免控制目标突变；射击任务在自瞄模式下还会结合视觉侧的开火许可决定是否拨弹。

这些细节体现出项目不是只追求“能动起来”，而是考虑了比赛中常见的异常情况：断电、掉线、模式切换、视觉目标丢失、热量不足、卡弹、电容状态变化等。把这些边界条件纳入控制逻辑，是比赛机器人代码从 demo 走向可用系统的重要标志。

### 11. IMU 姿态解算与数学库适配

项目包含 IMU 惯性测量单元相关模块，并参考四元数姿态解算方案。README 中还专门说明了 STM32CubeMX 中 DSP 库的适配问题，例如需要使用支持浮点单元的 `arm_cortexM4lf_math.lib`，以及扩展卡尔曼初始化时可能需要调整堆空间。

这说明项目不仅使用 IMU 数据，还考虑了嵌入式数学库、浮点性能和内存配置等底层适配问题。对于云台控制、自瞄反馈和底盘跟随来说，稳定的姿态解算是整条控制链路的基础。

### 12. 工程规范与可维护性设计

仓库 README 中明确提出了代码分层和贡献规范：`API` 层作为应用接口层，不应定义实体变量；`BSP` 层是唯一允许直接出现 STM32 HAL 库函数的代码层；项目中不建议跨层调用，并建议参考 Google C++ 风格指南。

这一点适合作为项目工程能力亮点：项目不只是堆功能，而是试图建立可维护的嵌入式机器人代码框架。对于 RoboMaster 这类多人协作、赛季迭代和高频调参的项目来说，清晰的模块边界和代码规范非常重要。


## 总结

- 设计并维护 Chassis/Gimbal 双工程嵌入式控制架构，按 `Application`、`BSP`、`Components`、`Drivers` 等层级拆分代码，提升驱动、算法和业务任务的复用性与可维护性。
- 基于 RTOS 任务调度实现底盘、云台、射击、通信、视觉等毫秒级周期任务，完成机器人多模块实时协同控制。
- 实现麦轮底盘运动解算与云台跟随控制，根据云台角度对底盘速度进行坐标变换，并支持跟随、小陀螺和失能保护等模式。
- 实现底盘功率限制控制，结合电机转速、电流、转矩估算和裁判系统功率上限进行功率分配，在规则约束内提升底盘动态性能。
- 实现云台手动/自瞄双模式控制，采用 yaw/pitch 角度环和速度环级联 PID，并加入前馈、角度归一化和 pitch 限位。
- 打通 STM32 与 MiniPC 的 USB CDC 视觉通信链路，周期发送 IMU 姿态数据并解析视觉返回的 yaw、pitch、distance 和开火许可。
- 实现弹道预测与补偿，根据目标速度、yaw 角速度、弹速、系统延迟和飞行时间预测装甲板位置，并迭代计算 pitch 补偿角。
- 实现射击热量管理和卡弹处理，根据裁判系统热量上限、当前热量和冷却值动态调整发弹频率，并通过电流检测触发拨盘反转退弹。
- 集成 RoboMaster 裁判系统串口 DMA 通信，解析机器人状态、功率热量、RFID 和初速等数据，并通过客户端 UI 显示超级电容、视觉、RFID 和准星状态。

我认为最能体现难度的是底盘功率控制和视觉自瞄闭环。底盘功率控制需要在裁判系统限制内最大化运动性能，因此项目根据电机转速、电流和转矩估算功率，并在功率超限时按 PID 误差和功率占比分配输出。视觉自瞄部分则通过 MiniPC 返回目标角度和距离，嵌入式端完成云台目标更新、双环 PID 控制和弹道补偿，最终驱动云台和射击机构协同工作。

此外，项目里还有很多实战细节，例如热量不足时自动限制射速、拨弹电机卡弹时反转退弹、云台目标丢失时回退人工控制、客户端 UI 显示超级电容与视觉状态等。这些设计说明项目不是只做了“能跑”的控制，而是考虑了比赛中的稳定性、可操作性和异常处理。
